# Требования (черновик, 2026-10-05)

> Исходные заметки. Актуальное ТЗ — [tz.md](tz.md): регистрация студентов перенесена из веб-формы в бота, бот — на C#. Модель данных ниже приведена к текущему коду.

Сайт — только для преподавателей (+ публичная форма для студентов). Telegram-бот — только для студентов (получение ДЗ и сдача).
Стек: C# backend (.NET 10), React frontend, Python бот (ходит в API бэкенда, не в БД; с Telegram взаимодействует только бот). Хостинг — Yandex Cloud: одна VM с docker compose (backend + bot + nginx) + Managed PostgreSQL, S3 = Yandex Object Storage, HTTPS + домен (позже).

## Предметы, группы, преподаватели
- Регистрации преподов нет — заводим вручную в БД (логин/пароль).
- Предмет (дисциплина) — отдельная сущность.
- Курс = предмет × подгруппа × семестр (например, «Тервер у ФИИТ-301-1, 2026 осень»). Семестр = год + осень/весна. Курс можно отправить в архив: он становится только для чтения и пропадает из активных списков.
- Подгруппа — часть группы (ФТ-201-1), НЕ привязана к предмету; одна и та же подгруппа может изучать разные предметы.
- Админ задаётся на курс — это тот, кто его создал (по факту ведёт практику). Для другого предмета админ той же подгруппы может быть другим.
- Админ может выдать доступ к своему курсу другому преподу. Доступ пока только полный.
- Препод ведёт несколько подгрупп; у предмета может быть несколько преподов.

## Сбор студентов
- Препод создаёт форму-ссылку со сроком действия (задаёт препод). Распространение ссылки — не наша забота.
- Форма создаётся под конкретные подгруппы препода (в рамках предмета); студент выбирает подгруппу из выпадающего списка.
- Студент вводит: имя, фамилию, подгруппу (выбор из списка), tg-аккаунт (только как подсказка), галочка согласия на обработку ПД.
- Привязка Telegram: после отправки формы — кнопка «Открыть бота» со ссылкой `t.me/<bot>?start=<одноразовый код>`; бот по коду привязывает tg user id к заявке.
- Препод видит список заявок: подтвердить по одному / всех, удалить. «Попросить перезаполнить» не делаем — препод удаляет заявку и сам заново шлёт студенту ссылку на форму.
- Студент может быть на нескольких предметах (решение универсальное).
- Если при привязке бота Telegram уже есть в базе — автоматически склеиваем с существующим студентом, имя берём из новой заявки.
- Препод может подтвердить студента без привязанного бота; в списке показываем значок «бот не привязан».
- Метки — опция: каждый препод заводит свои и навешивает на студентов.

## ДЗ
- ДЗ = внешняя ссылка на задание.
- Есть дедлайн. Сдача после дедлайна разрешена; преподу показываем, что сдано с опозданием, и время сдачи.
- ДЗ выдаётся в один или несколько курсов препода; видят его только преподы этих курсов. Адресаты внутри курсов: все / конкретные студенты / по меткам / отдельные курсы.
- Уведомление в бот — по кнопке «Опубликовать», получают только адресаты на момент публикации. Студент, добавленный в подгруппу позже, уведомление не получает, но видит ДЗ в боте и может сдать.
- Подзадачи с баллами — опционально, на усмотрение препода.
- Сдача: ровно один PDF, до 20 МБ (больше — бот отвечает, что файл слишком большой). Хранение в S3.
- Версионирование сдач: студент может присылать новые версии по одному ДЗ.
- Студент видит в боте список своих ДЗ со статусами.

## Проверка
- Сводная таблица студенты × ДЗ, кликабельные ячейки, фильтр по группе, экспорт в Excel.
- По клику — PDF, на котором препод рисует/пишет (слой аннотаций хранится отдельно, оригинал не меняется).
- Оценка: число, может быть дробной; возможна оценка по каждой подзадаче. Если подзадачи заданы — итог = сумма баллов, но препод может вписать итог вручную.
- Текстовый комментарий в свободной форме.
- Проверка привязана к версии сдачи. Новая версия после проверки → статус «на проверке», старые пометки остаются у старой версии.
- Препод может менять комментарии/пометки в любой момент; результат (оценка, комментарий, PDF с наложенным слоем препода) уходит студенту по кнопке «Отправить студенту».

## Модель данных
```
Teacher(id, login, password_hash, full_name, must_change_password, added_by_id?, created_at, disabled_at?, sessions_valid_from)
Subject(id, name, normalized_name unique)              -- общий справочник предметов
Group(id, name unique)                                 -- ФТ-201, name нормализован
Subgroup(id, group_id, number?)                        -- ФТ-201-1; number null = группа без деления
Course(id, subject_id, subgroup_id, semester_year, semester_term: Autumn|Spring, admin_teacher_id, created_at, archived_at?)
                                                       -- unique(subject, subgroup, semester); admin = ведущий преподаватель
CourseAccess(course_id, teacher_id)                    -- выданный ведущим полный доступ

Student(id, telegram_user_id unique, telegram_username, first_name, last_name, pd_consent_at, created_at, bot_blocked_at?)
Enrollment(id, student_id, course_id, invite_id?, status: Pending|Approved|Rejected|Removed, reject_reason, created_at, decided_at, decided_by_id)
                                                       -- активная (Pending/Approved) — одна на студента и курс
Invite(id, code unique, author_id, subject_id, expires_at?, closed_at?, created_at) + invite_courses(invite_id, course_id)
Tag(id, teacher_id, name) + StudentTag(tag_id, student_id)

Homework(id, subject_id, semester_year, semester_term, author_id, title, link, deadline, created_at, published_at?)
homework_courses(homework_id, course_id)               -- курсы ДЗ; препод видит ДЗ, если имеет доступ хотя бы к одному
HomeworkTarget(homework_id, kind: Student|Tag|Course, ref_id)  -- сужение адресатов внутри курсов; нет правил = все
HomeworkRecipient(homework_id, student_id, notified_at)        -- снапшот тех, кому ушло уведомление
Subtask(id, homework_id, order, title, max_score?)

Submission(id, homework_id, student_id, version, file_key, file_name, file_size, submitted_at)   -- опоздание вычисляется
Review(id, submission_id unique, updated_by_id, sent_by_id?, annotations jsonb, comment, total_override?, updated_at, draft_hash,
       sent_at?, sent_hash, sent_total, sent_comment, sent_subtasks jsonb, sent_file_key)       -- снапшот отправленного
SubtaskScore(review_id, subtask_id, score)
Notification(id, student_id, kind, text, homework_id?, file_key?, file_name?, status, attempts, available_at, locked_until?, sent_at?, last_error)
```
Статус ячейки сводной таблицы = последняя версия Submission + её Review: не сдано / на проверке / проверено (+ отправлено ли студенту), флаг опоздания.
