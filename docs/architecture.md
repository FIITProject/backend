# ФИИТ ДЗ: проект, решения, архитектура (2026-11-26)

Требования — [tz.md](tz.md) (актуальное ТЗ), исходные заметки — [requirements.md](requirements.md), запуск — [README](../README.md).

## О проекте

Сервис сдачи и проверки домашних заданий для ФИИТ.

- **Преподаватель** работает на сайте: заводит курсы и приглашает студентов, выдаёт ДЗ, проверяет работы пометками прямо на PDF и ставит баллы, ведёт сводную таблицу и выгружает её в Excel.
- **Студент** работает только в Telegram-боте: записывается по ссылке-приглашению, получает задания и дедлайны, сдаёт PDF, получает оценку, комментарий и PDF с пометками.

Сквозной сценарий:

1. Преподаватель создаёт курс: предмет, подгруппы, семестр.
2. Создаёт ссылку-приглашение и публикует её в чате группы.
3. Студент открывает ссылку в Telegram и заполняет анкету.
4. Преподаватель подтверждает заявку.
5. Преподаватель публикует ДЗ, студентам приходит уведомление.
6. Студент присылает PDF.
7. Преподаватель проверяет работу на сайте и отправляет студенту результат.

### Термины

| Термин | Что это |
|---|---|
| Предмет | общий справочник: «Теория вероятностей», «Python» |
| Курс (в API, `CourseDto`) | предмет × подгруппа × семестр, например «Тервер, ФТ-201-1, осень 2026». У курса есть ведущий преподаватель и коллеги с доступом; курс уходит в архив целиком |
| Курс (в интерфейсе) | как в дизайне: предмет в семестре со всеми подгруппами, к которым у преподавателя есть доступ |
| ДЗ | задание в одном или нескольких курсах одного предмета и семестра. Черновик, пока не опубликовано. Может иметь подзадачи с баллами |
| Сдача | версия работы студента: каждая присланная PDF — новая версия |
| Проверка | пометки на PDF, баллы по подзадачам или итог, комментарий. Черновик общий для преподавателей курса; «Отправить студенту» впечатывает пометки в PDF и отправляет результат |

## Компоненты

```
 Преподаватель ──HTTPS──► web (React SPA, статика в nginx) ──/api──► api (ASP.NET Core, .NET 10)
                                                                       ├─► PostgreSQL (Yandex Managed PG) — единственный владелец БД
                                                                       ├─► Object Storage (S3, приватный бакет): сдачи, PDF с пометками
                                                                       ├─► ClamAV (clamd): антивирус для сдаваемых PDF
                                                                       └─► outbox → RabbitMQ (очередь fiit.bot.notifications)
                                                                                         │
 Студент ◄──► Telegram ◄──► бот (C#, .NET) ◄── уведомления из очереди ───────────────────┘
                              └── X-Bot-Key: анкета, задания, сдача, статус доставки ──► api
```

| Компонент | Что делает | Технологии |
|---|---|---|
| api | вся бизнес-логика, права, единственный владелец БД и файлов | ASP.NET Core, .NET 10, EF Core + Npgsql, PDFsharp 6.2.4, ClosedXML, AWSSDK.S3, RabbitMQ.Client |
| migrate | применяет миграции БД и выходит; тот же образ, что api | `dotnet Fiit.Api.dll migrate` |
| web | сайт преподавателя | React 19 + TypeScript, Vite, react-router, pdfjs-dist; nginx |
| bot | общается со студентами в Telegram, доставляет уведомления | .NET 10 Worker, Telegram.Bot 22 (long polling) |
| PostgreSQL | данные | 17 (локально), Yandex Managed PostgreSQL (прод) |
| S3 | файлы сдач и проверенные PDF | Yandex Object Storage, локально RustFS |
| RabbitMQ | очередь уведомлений студентам | 4.1 |
| ClamAV | антивирус для сдаваемых PDF | clamav-debian 1.4 (clamd по TCP) |

Бот — отдельный процесс и единственный, кто общается с Telegram. Своей БД у него нет: данные — только через `/api/bot/*`, уведомления — из RabbitMQ.

| `docs` | ТЗ, исходные заметки, этот документ |

**Почему монорепа.** API, бот и сайт меняются вместе: новое поле в контракте (например, максимальный балл задания) правится в бэкенде, в типах фронта и на экране одним PR. Весь стек поднимается одной командой `docker compose up`. Макеты по-прежнему делаются в FIITProject/frontend: правки дизайна переносятся в `web/app` и сверяются с оригиналом в браузере. Если фронт будут вести отдельно, `web/app` переносится в свой репозиторий без изменений в коде: он общается с бэкендом только через `/api`.

## Сайт (web/app)

- **SPA на React.** Раздаётся nginx как статика и ходит в API по тому же origin через прокси `/api`, поэтому CORS не нужен. JWT хранится в `localStorage`; при 401 сайт возвращает на вход.
- **Вёрстка — дизайн без изменений.** CSS дизайна лежит в `src/styles` как есть, разметка страниц — те же классы. Каждая страница сверена с оригинальным HTML скриншотами при одном размере окна.
  - CSS страниц дизайна пересекаются: одинаковые классы, правила для `html` и `body`. Поэтому стиль страницы подключается только пока она открыта (`PageStyle`, импорт `?inline`).
  - Поведение скриптов дизайна перенесено, в том числе масштаб профиля (`profile.js`) и страницы проверки под окно (`fit-viewport.js`).
- **Курс в интерфейсе** — предмет в семестре со всеми подгруппами, маршрут `/c/:subjectId/:semester`. Вкладки курса: задания, сводная, студенты (и заявки), приглашения, преподаватели, настройки. Кнопка в шапке у каждой вкладки своя.
- **Функции из ТЗ, которым в дизайне нет отдельного места,** встроены в его элементы без изменения вида:
  - создание аккаунта коллеги — из поиска по логину на вкладке «Преподаватели»;
  - сброс пароля и отключение коллеги — по клику на его имя;
  - досрочное закрытие приглашения — в режиме изменения срока;
  - выбор адресатов ДЗ — окно по ссылке в «Общих сведениях» формы задания.
- **Код задания** (ДЗ-3, ДР-1, Г-2) — начало названия. Тип выбирается переключателем, номер присваивается по уже существующим заданиям курса. Набор типов хранится в браузере преподавателя.
- **Настройки колокольчика** (заявки, работы на проверку, пересдачи, просрочки) хранятся в браузере.
- **Колокольчик в реальном времени.** Вкладка держит поток SSE `GET /api/me/events`. После сохранения заявки, сдачи или проверки API шлёт событие (`LiveEventsInterceptor` на SaveChanges), и сайт перечитывает счётчики. В событии только вид изменения, данные и права — через обычные запросы. Рассылка в памяти процесса: при нескольких экземплярах API понадобится общий канал (Postgres LISTEN/NOTIFY или RabbitMQ). Просрочки зависят от времени, поэтому видимая вкладка перечитывает счётчики ещё и раз в минуту.
- **Проверка работы.**
  - PDF рендерится через pdf.js, слой пометок рисуется поверх: перо, маркер, текст, ластик; отмена — Ctrl/⌘+Z.
  - Черновик сохраняется сам через секунду после правки.
  - Страница проверки грузится отдельным чанком, вместе с pdf.js.

## Решения

1. **Курс = предмет × подгруппа × семестр.** Архивируется курс целиком: он становится только для чтения, ожидающие заявки отклоняются с причиной «Набор закрыт», приглашения закрываются. У курса есть ведущий преподаватель: он выдаёт доступ коллегам и удаляет пустой курс. Остальные права у преподавателей курса равные.
2. **Единственный владелец БД — бэкенд. Миграции — отдельный шаг деплоя.**
   - Схема задаётся миграциями EF Core (`Data/Migrations`).
   - Применяет их команда того же образа `dotnet Fiit.Api.dll migrate` до запуска новой версии API. В compose это сервис `migrate`, api стартует после его успешного завершения. В проде — job или шаг пайплайна перед раскаткой.
   - API со схемой старее своего кода не стартует.
   - Миграцию можно запускать под пользователем БД с правами на схему, а API — под пользователем только с правами на данные.
   - Правило: схема после миграции должна работать и со старой версией кода, пока та ещё запущена. Удаление колонки — следующим релизом.
   - `Db:MigrateOnStartup` — только для тестов и `dotnet run`.
3. **Бот — отдельный процесс на C#.**
   - Переиспользует `Fiit.Contracts`. Логика диалога (`Fiit.Bot.Core.Dialog`) не зависит от Telegram: её же использует эмулятор на старом сайте, так что сценарии проверяются без Telegram.
   - Шаг анкеты бот держит в памяти: после перезапуска незаконченная анкета начинается заново, всё остальное хранит API.
   - Long polling Telegram допускает один экземпляр бота.
   - Коды ошибок для бота — в `ProblemDetails.code` (`ErrorCodes`), текст ошибки бот показывает студенту как есть.
4. **Уведомления — transactional outbox и RabbitMQ.**
   - Уведомление создаётся строкой `notifications` с готовым текстом в той же транзакции, что и событие: подтверждение заявки, публикация или изменение ДЗ, отправка проверки. Поэтому оно не теряется и не появляется без события.
   - Фоновый публикатор в API (`NotificationOutboxPublisher`) берёт пачку `Pending` (`FOR UPDATE SKIP LOCKED`), публикует её в обменник `fiit.notifications` с подтверждением брокера и помечает `Published`.
   - Бот читает очередь `fiit.bot.notifications`, отправляет в Telegram и сообщает API `delivered` или `failed`.
   - Доставка «хотя бы один раз»: перед отправкой бот проверяет статус в API и пропускает уже доставленное.
   - Временная ошибка (сеть, 5xx, 429) — копия уходит в очередь повтора с TTL (от 10 с до 2 ч, около 4 часов суммарно) и потом возвращается в основную очередь.
   - Постоянная ошибка или исчерпанные попытки — сообщение уходит в `fiit.bot.notifications.dead` для ручного разбора, API получает `failed`.
   - Студент заблокировал бота (403) — `failed` с `botBlocked`, у преподавателя появляется значок «бот заблокирован».
   - Топологию объявляют и API, и бот, поэтому порядок запуска не важен. Публикация идёт с `mandatory`, так что неразосланное сообщение не теряется молча.
   - ДЗ можно опубликовать без уведомления (`publish?notify=false`). Адресаты всё равно фиксируются, ДЗ появляется у них в «Моих заданиях».
5. **Файлы.** Бот скачивает PDF из Telegram и отправляет его на бэкенд multipart-запросом. Размер (до 20 МБ) и тип бот проверяет по метаданным ещё до скачивания. Бэкенд кладёт файл в приватный бакет только после проверки (`SubmissionFileGuard`):
   - файл должен открываться PDFsharp в режиме изменения — тем же, которым потом впечатываются пометки; без пароля; не больше 300 страниц;
   - **без активного содержимого (`PdfSafety`):**
     - запрещены JavaScript, запуск программ, отправка форм, импорт данных, вложенные файлы, RichMedia, XFA;
     - проверяются все объекты документа, включая сжатые потоки объектов; имена с `#`-экранированием (`/J#61vaScript`) декодирует парсер;
     - эвристика как у pdfid. В сканах и выгрузках из Word или LaTeX такого не бывает, а преподаватель может открыть оригинал в Acrobat, где скрипты выполняются;
   - антивирус ClamAV по TCP (`INSTREAM`). Если clamd недоступен, файл не принимается (503 `scan_unavailable`, «попробуйте позже»): проверка закрыта по умолчанию;
   - отказ — 400 с кодом `not_pdf`, `pdf_encrypted`, `pdf_too_many_pages`, `pdf_unsafe` или `pdf_infected`; текст ошибки бот показывает студенту.

   Сайт и бот получают файлы **через API** с проверкой прав, а не по presigned-ссылкам: так проще и не нужен CORS на бакете. Все ответы API идут с `X-Content-Type-Options: nosniff`.
6. **Пометки на PDF** хранятся JSON-ом в координатах страницы PDF: пункты, начало — левый верхний угол. При «Отправить студенту» **бэкенд** впечатывает слой в копию PDF. Используется PDFsharp 6.2.4 — последняя MIT-версия, с 6.5 он под AGPL. Шрифт DejaVu Sans с кириллицей вшит в сборку.
7. **Проверяющий не закреплён.**
   - Черновик проверки общий для преподавателей курса: `updated_by_id` — кто последним правил, `sent_by_id` — кто отправил. Подпись отправившего видит студент.
   - Сохранение передаёт `baseUpdatedAt`. Если черновик тем временем сохранил коллега, API отвечает 409 `review_changed`, чтобы не затереть его правки.
   - «Есть неотправленные правки» определяется по хешу содержимого черновика, а не по времени: автосохранение без изменений не ломает статус.
8. **Баллы.**
   - Подзадачи необязательны.
   - Максимальный балл задания можно задать и без подзадач. Если у подзадач есть баллы, максимум равен их сумме и пересчитывается сам (`Homework.EffectiveMaxScore`).
   - Итог проверки — сумма баллов подзадач или число, введённое вручную.
   - Итоговый столбец сводной — среднее по проверенным ДЗ.
9. **Опоздание не хранится:** `submitted_at > deadline` считается по текущему дедлайну, поэтому продление дедлайна снимает опоздание.
10. **Время** хранится в UTC, показывается в часовом поясе Екатеринбурга (UTC+5, без перехода на летнее).
11. **Сессии.**
    - JWT живёт 14 дней.
    - На каждом запросе проверяется, что преподаватель активен и токен выпущен не раньше `teachers.sessions_valid_from`. Эта отметка сдвигается при отключении, смене и сбросе пароля.
    - С временным паролем доступны только `/api/me` и `/api/auth/change-password`.
    - Новый преподаватель заводится коллегой: тот получает временный пароль и передаёт его сам. Первый преподаватель создаётся командой `add-teacher`.

## API

Все ответы JSON (enum-ы строками), ошибки — ProblemDetails (`title` — текст для человека, `code` — для бота/фронта). Префикс `/api`.

### Бот (`X-Bot-Key`)
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/bot/invites/{code}` | приглашение: предмет, преподаватель, подгруппы; `isOpen=false` — набор закрыт |
| GET | `/bot/recruiting` | открытые наборы без ссылки: «предмет — преподаватель» + подгруппы (С-1.1а) |
| GET | `/bot/students/{tgId}` | известен ли студент, ФИО, заявки по курсам (С-1.2, С-1.9, С-1.10) |
| POST | `/bot/applications` | анкета `{telegramUserId, telegramUsername, inviteCode?, courseId, firstName, lastName, pdConsent}` |
| GET | `/bot/students/{tgId}/homeworks` | «Мои задания»: активные и «Завершённые» |
| GET | `/bot/students/{tgId}/homeworks/{hwId}` | карточка ДЗ: условие, версии, результат последней проверки |
| POST | `/bot/students/{tgId}/homeworks/{hwId}/submissions` | multipart `file` (PDF) → проверка файла → новая версия |
| GET | `/bot/notifications/{id}` | статус уведомления (`Pending` / `Published` / `Delivered` / `Failed`) — отсев повторной доставки |
| POST | `/bot/notifications/{id}/delivered` | отправлено в Telegram (повторный вызов ничего не меняет) |
| POST | `/bot/notifications/{id}/failed` | `{error, botBlocked}` — доставить не удалось |
| GET | `/bot/notifications/{id}/file` | PDF с пометками для уведомления о проверке |
| GET | `/bot/students/{tgId}/notifications?afterId=` | уведомления студента по порядку — для эмулятора бота |

Сами уведомления бот получает из RabbitMQ: обменник `fiit.notifications` (fanout) → очередь `fiit.bot.notifications`, тело — `BotNotificationDto` в JSON, `MessageId` — id уведомления, заголовок `x-attempt` — номер попытки.

## Права
Препод видит курс, если он ведущий или ему выдан доступ; ДЗ — если имеет доступ хотя бы к одному из курсов ДЗ; студента — если тот в его курсе. Проверка — на каждом эндпоинте (`Services/Access`), не на фронте. Архивный курс — только чтение: изменяющие запросы по нему → 409 `course_archived`.

## Хостинг и деплой
Прод — Yandex Cloud: одна VM с docker compose (migrate → api, web/nginx с HTTPS, бот, RabbitMQ, ClamAV) + Managed PostgreSQL + Object Storage. Порядок деплоя: собрать образы → `migrate` → api и web → бот. Из РФ Telegram API может быть недоступен — боту понадобится прокси или сервер, откуда Telegram открывается.

Локально `docker compose up -d --build` поднимает Postgres, RustFS (S3-совместимое хранилище), RabbitMQ, ClamAV, migrate, api, web (8080) и web-blazor с эмулятором бота (8081); Telegram-бот — с профилем `bot` и токеном в `.env` (`TELEGRAM_TOKEN`, `BOT_USERNAME`, при необходимости `TELEGRAM_PROXY` — SOCKS5/HTTP-прокси до Telegram). Подробно — в README.

## Открытые технические вопросы
- Фронт живёт в монорепе (`web/app`), а макеты — в FIITProject/frontend; если ребята будут писать React сами, `web/app` переносится в их репозиторий.
- Нет в API, хотя есть в дизайне: интеграция с Google Таблицами, факультет курса («ФИИТ» на карточках), дата последней смены пароля.
- ClamAV при первом запуске качает базы сигнатур (1–3 минуты, ~1 ГБ памяти); пока clamd не готов, сдача отвечает «попробуйте позже». Базы обновляет сам контейнер (freshclam).
- Состояние диалога бота в памяти: незаконченная анкета теряется при перезапуске бота. Если станет мешать — хранить в Redis или в API.
- Повёрнутые страницы PDF (`/Rotate`) и страницы с CropBox ≠ MediaBox: пометки могут сместиться при впечатывании.
