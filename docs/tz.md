# Техническое задание: сервис сдачи и проверки ДЗ

Версия: черновик 4, 2026-10-25 — приведено в соответствие с реализацией (PR #1). Все допущения прошлых версий приняты; что ещё не решено — раздел 7.

---

## 1. Общее

### 1.1. Цель
Преподаватель собирает студентов своих подгрупп, выдаёт им домашние задания, получает сдачи в PDF, проверяет их прямо на сайте (пометки на PDF, оценка, комментарий) и отправляет результат студенту. Студент регистрируется, получает задания и сдаёт их через Telegram-бота.

### 1.2. Роли
| Роль | Канал | Как появляется в системе |
|---|---|---|
| Преподаватель | Сайт | Первого заводят командой `add-teacher` на сервере, остальных добавляют другие преподаватели на сайте (самостоятельной регистрации нет) |
| Студент | Только Telegram-бот | Сам заполняет анкету в боте по ссылке-приглашению преподавателя |

### 1.3. Термины
| Термин | Значение |
|---|---|
| Предмет | Дисциплина, например «Python». |
| Группа | Учебная группа, например ФТ-201. |
| Подгруппа | Часть группы, например ФТ-201-1. Не привязана к предмету. Если группа не делится — одна подгруппа без номера. |
| Семестр | Год + «осень» или «весна», например «2026 осень». |
| Курс | Предмет × подгруппа × семестр, например «Тервер у ФИИТ-301-1, 2026 осень». Единица, к которой привязаны студенты, доступы и ДЗ. Курс можно отправить в архив. |
| Ведущий преподаватель | Преподаватель, создавший курс (ведёт практику). У одной подгруппы по разным предметам ведущие преподаватели могут быть разные. |
| Доступ | Ведущий преподаватель может выдать другому преподавателю полный доступ к своему курсу. |
| Приглашение | Ссылка на бота вида `t.me/<бот>?start=<код>`, которую преподаватель публикует в чате курса. Привязана к предмету, семестру и одному или нескольким курсам. |
| Анкета | Вопросы, на которые студент отвечает в боте: фамилия, имя, подгруппа, согласие на обработку ПД. |
| Заявка | Заполненная анкета, ожидающая решения преподавателя. |
| Метка | Произвольный ярлык, который преподаватель вешает на студентов (личный для каждого преподавателя). |
| ДЗ | Домашнее задание в одном или нескольких курсах одного предмета и семестра: название, внешняя ссылка на условие, дедлайн, необязательные подзадачи. |
| Адресаты | Кому выдано ДЗ внутри его курсов: конкретные студенты / по меткам / курсы целиком. |
| Сдача (версия) | Один PDF, присланный студентом по ДЗ. Каждая повторная сдача — новая версия. |
| Проверка | Пометки на PDF + оценка + комментарий к конкретной версии. За проверкой не закреплён преподаватель: проверять может любой преподаватель курса, подписывается тот, кто отправил. |

### 1.4. Статусы
**Заявка / студент в курсе:** `Ожидает подтверждения` → `Подтверждён` или `Отклонена`. После отклонения студент заполняет анкету заново — появляется новая заявка. Подтверждённого студента преподаватель может удалить из курса.

**ДЗ:** `Черновик` → `Опубликовано`.

**Курс:** `Активен` ⇄ `В архиве`.

**Ячейка «студент × ДЗ»** (вычисляется по последней версии):
| Статус | Условие |
|---|---|
| Не назначено | ДЗ не выдано этому студенту |
| Не сдано | Версий нет, дедлайн не прошёл |
| Не сдано, просрочено | Версий нет, дедлайн прошёл |
| На проверке | Последняя версия без проверки или проверка не отправлена ни разу |
| Проверено | Проверка последней версии отправлена студенту |
| Проверено, есть неотправленные правки | После отправки преподаватель изменил проверку |

Дополнительно у ячейки: флаг «сдано с опозданием» и номер версии, если их больше одной.

## 2. Пользовательские сценарии (сквозные)

### Сценарий А. Подготовка преподавателя
1. Первого преподавателя заводят командой `add-teacher` на сервере. Остальных добавляет на сайте любой уже существующий преподаватель (П-10) и передаёт им логин и временный пароль.
2. Преподаватель входит на сайт; при первом входе меняет временный пароль.
3. Создаёт предмет (или выбирает существующий).
4. Создаёт курсы: предмет + группа + подгруппа + семестр. Становится их ведущим преподавателем.
5. При необходимости выдаёт доступ к курсу коллеге.
6. По окончании семестра отправляет курсы в архив (П-2.5).

### Сценарий Б. Сбор студентов
1. Преподаватель создаёт на сайте приглашение: предмет и курсы (подгруппы) текущего семестра. Получает ссылку на бота и публикует её в общем чате курса со студентами.
2. Студент переходит по ссылке в бота. До подтверждения ему доступен только `/start`, остальной функционал закрыт.
3. После `/start` бот задаёт вопросы анкеты (вместо веб-формы): фамилия, имя, подгруппа, согласие на обработку ПД. Студент проверяет ответы и отправляет.
4. Заявка появляется у преподавателя на сайте. Преподаватель подтверждает (добавляет студента в курс) или отклоняет.
5. Если заявка отклонена — бот сообщает об этом студенту, и тот заполняет анкету заново.
6. После подтверждения студенту приходит уведомление в Telegram, и ему становится доступна сдача ДЗ по этому предмету.

### Сценарий В. Выдача ДЗ
1. Преподаватель создаёт ДЗ: название, ссылка на условие, дедлайн, при желании подзадачи и баллы.
2. Выбирает адресатов.
3. Нажимает «Опубликовать» — адресаты получают уведомление в боте.

### Сценарий Г. Сдача
1. Студент получает уведомление, открывает условие по ссылке, решает.
2. В боте выбирает ДЗ → «Сдать» → отправляет PDF.
3. Бот подтверждает приём (версия, время, пометка об опоздании, если после дедлайна).
4. При желании студент присылает новую версию.

### Сценарий Д. Проверка
1. Преподаватель открывает сводную таблицу предмета, фильтрует по группе.
2. Кликает на ячейку → открывается PDF.
3. Рисует и пишет на PDF, ставит оценку (итог или по подзадачам), пишет комментарий. Черновик сохраняется автоматически.
4. Нажимает «Отправить студенту».
5. Студент получает в боте оценку, комментарий и PDF с пометками.
6. Если студент присылает новую версию — ячейка возвращается в «На проверке», проверка старой версии остаётся при ней.

## 3. Функциональность преподавателя (сайт)

### П-1. Вход
- П-1.1. Вход по логину и паролю. При ошибке — «Неверный логин или пароль» (без уточнения, что именно неверно).
- П-1.2. Сессия живёт 2 недели, по истечении — возврат на страницу входа с сохранением адреса, куда шёл. Отключение преподавателя (П-10.4), смена и сброс его пароля (П-1.4, П-10.3) сразу завершают все его сессии.
- П-1.3. Выход из аккаунта на этом устройстве (сессии на других устройствах остаются; завершить все — сменить пароль).
- П-1.4. Смена своего пароля (старый + новый пароль). При первом входе с временным паролем смена обязательна.
- П-1.5. Восстановления пароля по почте в v1 нет — новый временный пароль может выдать любой преподаватель (П-10.3).

### П-2. Предметы и курсы
- П-2.1. Список предметов — общий для всех преподавателей. При создании — автодополнение по существующим, чтобы не плодить дубли («Python» и «python»).
- П-2.2. Создание курса: выбрать предмет, ввести группу и номер подгруппы (номер необязателен), выбрать семестр. По умолчанию подставляется текущий семестр: сентябрь–январь — осень, февраль–август — весна.
  - Группа нормализуется: верхний регистр, без лишних пробелов, единый формат дефиса (`фт 201` → `ФТ-201`). Ввод `ФТ-201-1` в поле группы автоматически раскладывается на группу `ФТ-201` и подгруппу `1`.
  - Если такой курс (предмет + подгруппа + семестр) уже существует — ошибка «У ФТ-201-1 по Python в семестре 2026 осень уже есть преподаватель (ФИО). Попросите у него доступ». В новом семестре тот же предмет у той же подгруппы заводится как новый курс.
  - Создатель становится ведущим преподавателем курса.
- П-2.3. Список «Мои курсы»: курсы, где преподаватель ведущий или имеет доступ. По умолчанию показываются только активные, переключатель «Архив» показывает архивные. Колонки: предмет, подгруппа, семестр, ведущий преподаватель, число подтверждённых студентов, число ожидающих.
- П-2.4. Удаление курса — только ведущий преподаватель и только пустого курса: без заявок (в том числе отклонённых) и без ДЗ. Курс с историей отправляют в архив.
- П-2.5. Архивация курса:
  - отправить в архив может ведущий преподаватель или преподаватель с доступом; можно выбрать сразу несколько курсов (например, все свои курсы за семестр);
  - вернуть из архива можно так же;
  - архивный курс доступен только для чтения: студенты, сдачи, проверки, сводная таблица и экспорт открываются, но нельзя подтверждать заявки, выдавать ДЗ, проверять и отправлять проверки;
  - приглашения, в которых есть только архивные курсы, закрываются; архивный курс исчезает из выбора подгрупп в боте;
  - ожидающие заявки в архивный курс отклоняются с причиной «Набор закрыт», студенту приходит уведомление об отклонении (С-2.2);
  - студент видит ДЗ курса в «Мои задания» в разделе «Завершённые», сдать новую версию не может (С-5.6).

### П-3. Доступы
- П-3.1. Ведущий преподаватель курса видит список преподавателей с доступом, может выдать доступ (выбор преподавателя из списка всех преподавателей) и отозвать.
- П-3.2. Доступ полный: всё, что может ведущий преподаватель, кроме управления доступами и удаления курса.
- П-3.3. Передать роль ведущего преподавателя в v1 нельзя.

### П-4. Приглашения в бота
- П-4.1. Создание приглашения: предмет, один или несколько активных курсов этого предмета в одном семестре (из доступных преподавателю), срок действия (необязательно).
- П-4.1а. Активные приглашения также определяют, что увидит студент, который запустил бота без ссылки (см. С-1.1а).
- П-4.2. После создания — ссылка на бота `t.me/<бот>?start=<код>` и кнопка «Скопировать». Преподаватель сам публикует её в чате курса.
- П-4.3. Список приглашений: предмет, подгруппы, срок, статус (активно / истекло / закрыто), число заявок.
- П-4.4. Изменить срок, закрыть досрочно.
- П-4.5. По истёкшему или закрытому приглашению бот отвечает «Набор закрыт, обратитесь к преподавателю».

### П-5. Список студентов и модерация
- П-5.1. Экран курса (или нескольких — фильтр по подгруппам) со списком студентов.
- П-5.2. Колонки: фамилия, имя, подгруппа, Telegram (@ник, берётся из Telegram автоматически), статус, дата заявки, метки.
- П-5.3. Фильтры: статус, подгруппа, метка; поиск по фамилии.
- П-5.4. Действия с заявками:
  - подтвердить одну;
  - подтвердить выбранные / все ожидающие в текущем фильтре;
  - отклонить, с необязательной причиной, которую увидит студент.
- П-5.5. Действия с подтверждёнными студентами: удалить из курса (с подтверждением «Удалить Иванова Ивана из ФТ-201-1 по Python?»). Студенту уведомление не отправляется.
- П-5.6. Удаление подтверждённого студента, у которого уже есть сдачи: сдачи и проверки сохраняются, студент пропадает из списков и таблицы.
- П-5.7. Дублей нет по построению: студент определяется по Telegram-аккаунту, у одного аккаунта может быть только одна активная заявка в один курс.

### П-6. Метки (необязательная функция)
- П-6.1. Метки личные: каждый преподаватель видит только свои.
- П-6.2. Создать, переименовать, удалить метку.
- П-6.3. Повесить/снять метку с одного или нескольких выбранных студентов в списке П-5.

### П-7. Домашние задания
- П-7.1. Список ДЗ предмета в выбранном семестре: название, дедлайн, статус (черновик / опубликовано), сдано X из Y, проверено Z из X. Преподаватель видит только ДЗ своих курсов: ДЗ, у которых среди курсов (П-7.2) есть курс, где он ведущий или имеет доступ. ДЗ коллег из других курсов того же предмета не видны.
- П-7.2. Создание ДЗ (сохраняется как черновик):
  - название (обязательно);
  - ссылка на условие (обязательно, валидный URL);
  - дедлайн — дата и время (обязательно);
  - подзадачи (необязательно): список «название + максимальный балл (необязательно)», порядок можно менять;
  - курсы ДЗ (обязательно) — один или несколько активных курсов этого предмета и семестра из доступных преподавателю; по умолчанию все такие курсы;
  - адресаты — по умолчанию все студенты выбранных курсов; можно сузить до любой комбинации (объединения) конкретных студентов, меток и отдельных курсов — только среди студентов выбранных курсов. Показывается итоговое число студентов.
- П-7.3. Черновик можно редактировать и удалять.
- П-7.4. «Опубликовать» — окно подтверждения «ДЗ получат N студентов» → публикация, уведомления адресатам.
- П-7.5. Адресаты фиксируются на момент публикации: уведомления получают только они. Студент, который попал в курс/метку позже, уведомления не получает, но видит ДЗ в боте и может сдать.
- П-7.6. После публикации можно (круг адресатов — только расширять, сузить нельзя):
  - менять название и ссылку — без уведомления;
  - менять дедлайн — адресаты получают уведомление «Дедлайн изменён: было → стало» (С-3.3);
  - менять подзадачи — только пока нет ни одной проверки с баллами по подзадачам; адресаты получают уведомление с новым списком подзадач (С-3.3);
  - добавлять адресатов — новые адресаты получают уведомление о ДЗ.
  - При сохранении изменений дедлайна или подзадач — галочка «Уведомить студентов», включена по умолчанию.
  - Опоздание считается от текущего дедлайна: если дедлайн продлили, сдачи до нового дедлайна перестают считаться опоздавшими.
- П-7.7. Удалить опубликованное ДЗ нельзя, если по нему есть сдачи.

### П-8. Сводная таблица
- П-8.1. Выбор предмета и семестра (по умолчанию — текущий). Строки — студенты своих курсов (фамилия, имя, подгруппа), столбцы — опубликованные ДЗ своих курсов (П-7.1) по возрастанию дедлайна.
- П-8.2. Ячейка показывает статус (см. 1.4), оценку, если проверено, флаг опоздания, номер версии (если > 1). Цвет по статусу.
- П-8.3. Итоговый столбец — средняя оценка студента по проверенным ДЗ (учитываются только отправленные проверки; несданные и непроверенные ДЗ в среднее не входят). Другие итоговые показатели — позже.
- П-8.4. Фильтры: группа, подгруппа, метка. Сортировка по фамилии.
- П-8.5. Клик по ячейке со сдачей → экран проверки (П-9). При наведении на проверенную ячейку видно, кто проверил. Клик по ячейке без сдачи — ничего.
- П-8.6. Шапка столбца: клик → карточка ДЗ (дедлайн, ссылка, сдано/проверено).
- П-8.7. Экспорт в Excel текущего вида с учётом фильтров: ФИО, группа, подгруппа, по каждому ДЗ — оценка (или статус текстом), отметка опоздания, итог.

### П-9. Проверка работы
- П-9.1. Проверяющий не назначается: любую работу курса может проверить любой преподаватель, который ведёт курс или имеет к нему доступ. Одно ДЗ (и даже одну работу) могут проверять разные преподаватели — например, один начал, другой продолжил и отправил.
- П-9.2. Экран: слева/по центру PDF, справа панель проверки.
- П-9.3. Просмотр PDF: листание страниц, масштаб, подгонка по ширине.
- П-9.4. Инструменты пометок: перо (цвет, толщина), текст (цвет, размер), маркер-выделитель, ластик, отмена/повтор. Пометки привязаны к странице и не съезжают при масштабе.
- П-9.5. Панель проверки:
  - студент, ДЗ, дедлайн, время сдачи, пометка «сдано с опозданием на X»;
  - переключатель версий (v1, v2, …): старые версии открываются вместе со своими пометками только для просмотра;
  - если есть подзадачи — поле балла по каждой (дробные числа, не выше максимума, если он задан); итог считается суммой;
  - поле «Итог» — можно вписать вручную, тогда сумма игнорируется (кнопка «Вернуть сумму»);
  - если подзадач нет — только «Итог»;
  - комментарий — свободный текст.
- П-9.6. Черновик проверки (пометки, баллы, комментарий) сохраняется автоматически; индикатор «Сохранено».
- П-9.7. «Отправить студенту»: генерируется PDF с впечатанными пометками, студенту уходят оценка, комментарий и этот PDF. Оценка для отправки не обязательна.
- П-9.8. После отправки можно продолжать править; статус «есть неотправленные правки». Повторное «Отправить» шлёт студенту обновлённый результат.
- П-9.9. Подпись: студенту и в сводной таблице показывается тот, кто отправил проверку (при повторной отправке — последний отправивший). В панели проверки видно, кто последним правил черновик и кто отправил.
- П-9.10. Если черновик открыт у двух преподавателей и один успел сохранить изменения, второму при сохранении показывается «Эту проверку только что изменил(а) ФИО — обновите страницу»; молча затереть чужие правки нельзя.
- П-9.11. Навигация: «Следующий студент» и «Следующая непроверенная» в рамках этого ДЗ и текущего фильтра.
- П-9.12. Скачать оригинальный PDF студента и отправленный PDF с пометками.

---

### П-10. Преподаватели
- П-10.1. Любой преподаватель может добавить другого преподавателя: ФИО, логин (например, почта). Система генерирует временный пароль и показывает его один раз — добавивший сам передаёт данные коллеге.
- П-10.2. Список преподавателей: ФИО, логин, кто добавил, дата добавления, статус (активен / отключён).
- П-10.3. Сбросить пароль коллеге — выдаётся новый временный пароль.
- П-10.4. Отключить преподавателя — может только тот, кто его добавил. Отключённый не может войти; его курсы, ДЗ и проверки сохраняются. Удаления в v1 нет.
- П-10.5. Добавление преподавателя не даёт ему доступа к чужим курсам — доступ выдаёт ведущий преподаватель курса (П-3).

## 4. Функциональность студента

### С-1. Вход в бота и анкета
- С-1.1. Студент переходит по ссылке-приглашению из чата курса и жмёт Start. Предмет и список подгрупп берутся из приглашения.
- С-1.1а. Если студент запустил бота без ссылки (просто `/start`), бот показывает список предметов, по которым сейчас идёт набор, в виде «Предмет — преподаватель». Набор идёт, если есть хотя бы одно активное приглашение. После выбора предмета на шаге «подгруппа» показываются подгруппы из активных приглашений по этому предмету. Если набора нет ни по одному предмету — «Сейчас нет открытых наборов, попросите у преподавателя ссылку».
- С-1.2. До подтверждения хотя бы в одном курсе студенту доступен только `/start`. На любые другие команды и сообщения бот отвечает «Сначала заполните анкету» или «Заявка на рассмотрении у преподавателя».
- С-1.3. Если приглашение истекло или закрыто — «Набор закрыт, обратитесь к преподавателю».
- С-1.4. Бот показывает, куда записывается студент (предмет, преподаватель), и задаёт вопросы по очереди:
  1. фамилия (текст);
  2. имя (текст);
  3. подгруппа — кнопки с подгруппами из приглашения;
  4. согласие на обработку персональных данных — текст согласия и кнопка «Согласен». Без согласия регистрация не продолжается.
- С-1.5. Валидация ответов: фамилия и имя — непустые, только буквы, пробел и дефис, до 100 символов.
- С-1.6. Сводка «Проверьте: Иванов Иван, ФТ-201-1, Python» с кнопками «Отправить» и «Заполнить заново».
- С-1.7. После отправки: «Заявка отправлена преподавателю. Мы сообщим, когда её рассмотрят».
- С-1.8. Telegram ID и @ник берутся из Telegram автоматически, студент их не вводит.
- С-1.9. Студент, уже известный боту (записан на другой предмет), по новому приглашению отвечает только на вопрос о подгруппе, ФИО предлагается подтвердить кнопкой «Да, это я» или исправить. Согласие на ПД повторно не спрашивается.
- С-1.10. Повторный переход по тому же приглашению, пока заявка на рассмотрении, — «Заявка уже на рассмотрении». Если студент уже подтверждён в этом курсе — «Вы уже записаны».

### С-2. Решение по заявке
- С-2.1. Подтверждение: «Вас добавили: Python, ФТ-201-1, преподаватель Иванов И. И. Теперь вам доступны задания» + кнопка «Мои задания». Открывается функционал сдачи ДЗ по этому предмету.
- С-2.2. Отклонение: «Заявка на Python отклонена» + причина, если преподаватель её указал, + кнопка «Заполнить заново» → анкета С-1.4 с начала.
- С-2.3. ДЗ по предмету, на который заявка ещё не подтверждена, студент не видит и сдать не может.

### С-3. Уведомления о ДЗ
- С-3.1. Приходит при публикации: предмет, название, дедлайн, ссылка на условие, кнопка «Сдать».
- С-3.2. Если студент заблокировал бота — уведомление не доставляется, у преподавателя в списке студентов значок «бот заблокирован».
- С-3.3. Изменение ДЗ после публикации (П-7.6): предмет, название, что изменилось (дедлайн: было → стало; подзадачи: новый список), кнопка «Сдать». Приходит всем адресатам, включая тех, кто уже сдал.

### С-4. Мои задания
- С-4.1. Команда `/tasks` и кнопка меню «Мои задания».
- С-4.2. Список ДЗ активных курсов, сгруппированный по предметам, сначала с ближайшим дедлайном. ДЗ архивных курсов — в отдельном разделе «Завершённые». У каждого: название, дедлайн, статус (не сдано / просрочено / на проверке / проверено: оценка).
- С-4.3. Карточка ДЗ: ссылка на условие, дедлайн, список версий (номер, время, «с опозданием»), результат последней проверки (если отправлен), кнопка «Сдать» / «Пересдать».

### С-5. Сдача
- С-5.1. «Сдать» → бот просит прислать один PDF, есть кнопка «Отмена».
- С-5.2. Проверки:
  - не PDF → «Нужен файл в формате PDF»;
  - больше 20 МБ → «Файл слишком большой, максимум 20 МБ»;
  - несколько файлов разом → принимаем первый, предупреждаем.
- С-5.3. Успех: «Принято: Python — ДЗ 3, версия 2, 05.10 14:30». После дедлайна — добавляется «сдано после дедлайна».
- С-5.4. Сдавать можно и после дедлайна, и после проверки; каждая сдача — новая версия, статус → «На проверке».
- С-5.5. Если студент присылает PDF без нажатия «Сдать» — бот спрашивает, к какому ДЗ его отнести (список открытых ДЗ).
- С-5.6. По ДЗ архивного курса сдать нельзя: «Курс завершён, сдача закрыта».

### С-6. Результат проверки
- С-6.1. Приходит сообщение: предмет, ДЗ, версия, оценка (итог и баллы по подзадачам, если есть), комментарий преподавателя, кто проверил («Проверил(а): Иванов И. И.» — тот, кто отправил), PDF с пометками.
- С-6.2. При повторной отправке после правок — новое сообщение с пометкой «Проверка обновлена».

### С-7. Команды бота
`/start` — регистрация по приглашению / приветствие (доступна всегда); после подтверждения: `/tasks` — мои задания, `/help` — справка.

## 5. Нефункциональные требования
- Н-1. Только HTTPS (терминирует nginx на сервере); домен — позже.
- Н-2. Пароли преподавателей — только хеш (bcrypt).
- Н-3. Файлы в приватном бакете Yandex Object Storage (локально — S3-совместимое хранилище RustFS). Сайт и бот получают файлы только через API с проверкой прав, прямых ссылок на бакет нет.
- Н-4. Права проверяются на сервере: преподаватель видит только курсы, где он ведущий или имеет доступ, и всё, что к ним относится.
- Н-5. Время хранится в UTC, показывается в часовом поясе Екатеринбурга (UTC+5).
- Н-6. Сайт преподавателя — десктопные Chrome / Firefox / Safari / Яндекс Браузер последних версий. У студента веб-интерфейса нет.
- Н-7. Уведомления не теряются при перезапуске сервисов (очередь в БД, повторные попытки).
- Н-8. Резервные копии БД — средствами Managed PostgreSQL.
- Н-9. Согласие на обработку ПД (нажатие «Согласен» в боте) фиксируется с датой и временем.

## 6. Вне рамок v1
Самостоятельная регистрация преподавателей и восстановление пароля по почте; веб-форма для студентов; напоминания о дедлайнах; разграничение уровней доступа; форматы кроме PDF и склейка фото; передача роли ведущего преподавателя.

## 7. Открытые вопросы
1. Сужение адресатов после публикации запрещено, чтобы у студента не пропадало выданное ДЗ (П-7.6). Оставляем так?
2. Уведомлять ли студента об отклонении заявки при архивации курса или отклонять молча (П-2.5)?
3. Итоговое среднее считается только по проверенным ДЗ (П-8.3). Считать ли несданные ДЗ нулём?
4. Текст согласия на обработку персональных данных (С-1.4) — нужен юридически выверенный текст; сейчас заглушка.
5. Повёрнутые страницы PDF: при впечатывании пометки могут сместиться (П-9.7).
6. Если преподаватель, который добавил коллег, ушёл, отключить их можно только через БД (П-10.4).
7. Telegram-бот: отдельный процесс на C#; нужен токен от @BotFather и имя бота для ссылок. До этого сценарии раздела 4 проверяются через эмулятор бота на сайте.
